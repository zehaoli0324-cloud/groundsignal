## 一、执行摘要

**建议切入口**：优先做能实际重跑、能检验科学错误、能嵌入明确工作流的窄域评测。对本项目而言，可先从单细胞与扰动分析、证据检索或科研数据分析工作流中选择一个，完成小规模参考解与独立评分。

当前版图的价值在于横向组织来源：45 条记录覆盖 10 类主领域，六张表把任务、机构和价值描述联系起来。但现有质量评分均是 provisional 初评，尚不能作为已完成的科学审计或市场估值依据。

实用意义应按决策拆分：知识与对话评测支持发布前筛查；预测与设计评测支持方法选择和实验前排序；多步 Agent 与复现评测支持工作流委托和回归验收。

市场线索已有，但需要区分口径。上海 AI Lab 在 2026-07-30 的官方更新中披露 MedBench 累计完成超过 31 万次评测，这是平台级采用信号，不是本项目收入，也不证明评测业务的合同金额。[R09]

建议的产品顺序是：公开窄域样例和研究报告 → 有明确客户问题的私有评测试点 → 模型与数据更新后的持续回归。客户、价格与复购需要实际试点验证，本报告不虚构市场规模或收费区间。

分类是本报告为阅读设计的分组，组间可能有合作交叉，不用于计算市场份额。FutureHouse、合作公司和开放社区不应被强行归为同一种商业主体。

**机构核验中的三个修正**：Google 是 MultiMedQA 套件的汇编者，组件仍有独立归属；BixBench 官方仓库写明 FutureHouse 与 ScienceMachine 合作，与现有 CSV 的 Edison Scientific 描述存在差异；Microsoft 的具体研究团队应以各项目作者与发布说明为准。[R05-R07,R13]

机构可能是创建者、维护者、托管方、数据提供方或采用方。合作关系和公司采用评测都不自动产生所有权；品牌归属也不等于评测质量。

## 四、各大类的实用意义 1/5


### 01  临床医学与医学知识  / 9 条登记

登记项目：MedQA-USMLE、MedMCQA、MultiMedQA、HealthBench、MedXpertQA、MedBench、CMB、CMExam、MSDiagnosis

为医疗模型建立知识、沟通和安全底线，帮助定位发布前需要人工复核的失败场景。

| 维度 | 实用意义与验证要求 |
| --- | --- |
| 实际工作 | 医疗问答、医学教育、患者沟通与诊疗信息辅助。考试题检验知识，开放式对话更适合检查澄清问题、表达不确定性和识别风险。 |
| 谁会使用 | 医疗模型团队、健康平台、医学教育产品和医院信息部门；这是潜在用户画像，不能据此认定已经采购。 |
| 关键决策 | 选择基础模型、决定哪些问题交给人工、检查版本升级是否增加危险回答；先按人群和场景分层，再看总体平均分。 |
| 怎样验收 | 知识题正确率之外，报告严重错误率、遗漏关键建议的比例、专家一致性与置信度校准。HealthBench 的医生量表提供开放式评分实例。[R01] |
| 能形成的价值 | 把模型升级变成重复安全回归，减少专家逐次从零评审的工作；实际节省量须与人工流程配对测量。 |
| 能力边界 | 考试高分不能证明临床结局改善；医院部署还需要本地病例、流程验证和持续监测。MedBench 与 MedXpertQA 应明确版本及任务范围。[R08-R10] |


### 02  生物医学 NLP 与证据检索  / 3 条登记

登记项目：PubMedQA、BioASQ、CBLUE

把检索和抽取结果变成能支持具体主张的证据，适合文献研究、知识库与研发情报工作。

| 维度 | 实用意义与验证要求 |
| --- | --- |
| 实际工作 | 检索论文、抽取疾病与药物关系、回答证据问题、为综述和研发判断整理引用。BioASQ 包含检索与问答挑战，可区分找不到证据和解释错误。[R11] |
| 谁会使用 | 药企情报团队、医学知识服务、科研搜索产品和知识库维护者。 |
| 关键决策 | 选检索系统和模型、决定某条关系是否进入知识库、识别哪些结论需要进一步检索；更适合支撑证据工作流的局部决策。 |
| 怎样验收 | 联合检查检索召回、证据与主张的对应性、引用定位、答案忠实度、时间有效性和无法回答时的弃答行为。 |
| 能形成的价值 | 降低重复搜索与引用核对成本，形成可审计的知识更新服务；应测量每条有效证据成本和专家复核时间。 |
| 能力边界 | 摘要问答正确不等于完成系统综述，也不证明因果结论。要处理反证、重复研究、研究对象差异和失效证据。 |

### 03  生物科研 Agent 与实验工作流  / 5 条登记

登记项目：LAB-Bench、BixBench、BioMysteryBench、LifeSciBench、BiomniBench-DA

判断 AI 能否完成可复现的研究辅助工作，并识别代码运行与科学分析之间的差距。

| 维度 | 实用意义与验证要求 |
| --- | --- |
| 实际工作 | 读取组学文件、检索数据库、编写分析脚本、执行工具、解释结果与形成可交接的研究材料。LAB-Bench 和 BixBench 分别提供基础研究能力与开放式分析入口。[R12-R13] |
| 谁会使用 | 药企研发、计算生物学团队、科研软件与 Agent 平台。 |
| 关键决策 | 选择哪些分析环节可以委托 AI，确定需要专家介入的位置，比较模型与工具配置，而不是只比较聊天回答。 |
| 怎样验收 | 同时记录科学结果、关键假设、数据质控、干净环境重跑、错误恢复与成本。BioMysteryBench 的客观元数据任务可用于验证结果；过程评审需明确允许多种方法。[R04] |
| 能形成的价值 | 减少分析准备和重复运行的时间，为真实工作流构建版本回归与专家失败库。LifeSciBench 覆盖更广泛研究任务。[R02] |
| 能力边界 | 任务成功不代表自动完成新发现；不能奖励固定分析路径或文件数量。BiomniBench-DA 的过程评测可作方法参考，具体评分需核验。[R14] |


### 04  遗传学与基因组学  / 2 条登记

登记项目：GeneBench、GeneBench-Pro

检验模型能否从复杂数据中提出合适的分析问题，并在混杂和不确定性下作出可支持的判断。

| 维度 | 实用意义与验证要求 |
| --- | --- |
| 实际工作 | 遗传关联、数量遗传学、组学统计与转化研究中的多阶段分析。GeneBench-Pro 强调数据探索、目标估计量和分析方案的修订。[R03] |
| 谁会使用 | 基因组研究团队、药物靶点研究、遗传分析软件与计算生物学模型团队。 |
| 关键决策 | 数据是否支持当前问题、该采用哪个模型、是否需要修改目标估计量、结论是否足以进入后续验证。 |
| 怎样验收 | 检查样本与批次结构、模型假设、效应估计、置信区间、多重检验和敏感性分析；给统计上等价且科学合理的解法留空间。 |
| 能形成的价值 | 降低因混杂、样本依赖或统计错误导致的返工，为研究审查与分析验收提供可复用任务。 |
| 能力边界 | 这两项是计算研究评测，不能直接替代临床变异分级或遗传咨询认证。临床遗传解读需要独立的证据与患者场景评测。 |

### 05  功能基因组学与单细胞  / 3 条登记

登记项目：Open Problems in Single-Cell Analysis、scIB、GEARS

为方法选择与扰动预测提供量化依据，适合虚拟细胞和靶点筛选的有限范围验证。

| 维度 | 实用意义与验证要求 |
| --- | --- |
| 实际工作 | 单细胞整合、批次校正、标签迁移与扰动后的表达预测。Open Problems 提供任务化比较，scIB 同时关注批次消除和生物信息保留。[R15-R16] |
| 谁会使用 | 单细胞分析平台、功能基因组学团队、靶点研究与虚拟细胞模型研发者。 |
| 关键决策 | 选整合方法、判断哪些候选扰动值得进入实验、筛查模型是否在新基因或新组合上失效；GEARS 提供扰动预测入口。[R17] |
| 怎样验收 | 以生物重复和条件为单位划分数据，比较无变化、均值和单扰动基线；报告差异基因、状态分布及组合扰动效应，而非只有整体相关性。 |
| 能形成的价值 | 帮助减少明显无效候选与错误分析路径，把模型定位为实验前排序的一层；需通过留出实验或前瞻实验测量筛选增益。 |
| 能力边界 | 一个细胞系的表达预测不能外推为患者药效；批次混合漂亮也可能抹除真实生物差异。随机划分和多数不变基因易掩盖问题。 |


### 06  蛋白质与结构生物学  / 7 条登记

登记项目：ProteinBench、PXMeter、PXDesignBench、ProteinGym、FLIP/FLIP2、CASP、CAMEO

分别检查结构、设计和突变效应，帮助决定模型及候选是否值得进入下一轮实验。

| 维度 | 实用意义与验证要求 |
| --- | --- |
| 实际工作 | 结构预测、复合物评估、骨架与序列设计、突变效应排序。ProteinBench 强调多指标，PXMeter 和 PXDesignBench 提供结构与设计评测工具。[R18-R20] |
| 谁会使用 | 抗体、酶工程、蛋白药物研发和结构模型团队。 |
| 关键决策 | 选结构模型、筛除不合理设计、确定突变和候选的实验优先级。各子任务应独立比较，结构分数与功能分数不可直接合并。 |
| 怎样验收 | 结构误差、界面质量、物理合理性、序列多样性和实验功能分别报告；ProteinGym 用实验突变测量检查排序能力。[R21] |
| 能形成的价值 | 用统一协议做模型选择和实验前过滤；CASP 盲测与 CAMEO 连续评估提示应采用时间留出和新目标检验。[R22-R23] |
| 能力边界 | 预测置信度不是结合、活性或可开发性证据。候选要成为药物，还需表达、稳定性、选择性和适用实验条件的独立验证。 |

### 07  药物发现与分子机器学习  / 7 条登记

登记项目：Therapeutics Data Commons、MoleculeNet、LIT-PCBA、PoseBusters、DUD-E、GuacaMol、MOSES

为分子筛选管线的具体一层提供证据，检查排序、性质预测和生成候选是否优于基础方法。

| 维度 | 实用意义与验证要求 |
| --- | --- |
| 实际工作 | 性质与 ADMET 预测、虚拟筛选、对接、分子生成和候选排序。TDC 将不同治疗相关任务组织为独立数据与评测组。[R24] |
| 谁会使用 | 药企发现团队、CRO、化学信息学软件与分子模型研发者。 |
| 关键决策 | 采用哪种排序或过滤方法、把有限实验预算分给哪些候选、如何设置弃答或适用域。 |
| 怎样验收 | 使用骨架、靶点或时间留出；在固定实验预算下报告富集与命中，同时检查校准和物理合理性。PoseBusters 可识别不合理分子姿态。[R25] |
| 能形成的价值 | 减少低质量候选进入昂贵实验的机会，形成项目级回归和私有测量评测；节省成本须扣除推理、复核与后续验证。 |
| 能力边界 | 对接合理不等于有活性，性质预测不等于体内药效，分子新颖不等于可合成。公开任务平均分不代表整条研发管线效率。 |


### 08  医学影像与数字病理  / 5 条登记

登记项目：GMAI-MMBench、MedMNIST、MIMIC-CXR、CheXpert、CAMELYON

评估影像分类、图文一致性与病理识别，为影像软件选型和本地部署验证提供依据。

| 维度 | 实用意义与验证要求 |
| --- | --- |
| 实际工作 | 胸片分类、图像与报告建模、病理切片识别及多模态问答。MIMIC-CXR 提供影像与放射报告，是一种临床数据入口。[R26] |
| 谁会使用 | 医学影像模型团队、医院信息与放射部门、病理软件企业。 |
| 关键决策 | 选择适合目标设备、医院和病例分布的模型，决定哪些结果交由医生复核。小型标准化集适合工程初测，不能承担全部部署验收。 |
| 怎样验收 | 按患者与医院划分，检查关键病变灵敏度、特异度、校准、漏报和图文矛盾；采用设备变化与外部中心测试。 |
| 能形成的价值 | 形成医院或设备场景的持续回归，发现新模型的漏诊风险；用户收益需要观察真实复核时间和流程影响。 |
| 能力边界 | 离线分数不等于临床获益。MIMIC-CXR 有认证与数据使用要求；取得访问权限不自动授权公开再分发。[R26] |

### 09  临床时间序列与医疗 Agent  / 2 条登记

评估模型如何主动获取信息、选择下一步行动，以及能否完成医疗数据工作流。

| --- | --- |

## 五、尚未作为主领域收录的两类


### 11  公共卫生与健康服务

实际意义：检验人群风险预测、资源分配、健康管理与干预评估，支持公共卫生机构和健康服务平台决定在哪里配置有限资源。现有临床知识题可以邻近涉及这些主题，但不代表已建立专门的人群任务集。

| 要解决的问题 | 适合的验证 |
| --- | --- |
| 疾病或服务需求预测 | 时间与地区留出；报告预测误差、校准及分层公平性。 |
| 干预效果评估 | 明确对照、目标人群和因果假设；预测相关性不能代替干预效果。 |
| 资源分配 | 模拟或实际受控试点中比较服务覆盖、等待时间和资源成本。 |


### 12  数据质量、安全与评测基础设施

实际意义：保证模型分数可以比较、失败可以解释、版本变化可以追踪。它既可成为独立评测方向，也应成为前面十类共同使用的底层协议。

| 要解决的问题 | 适合的验证 |
| --- | --- |
| 污染与泄漏 | 时间留出、相似样本扫描、答案隔离与权限检查。 |
| 评分可靠性 | 正例、反例、等价解、无变化基线与专家一致性；明确错误评分的概率。 |
| 可重复执行 | 固定环境、数据哈希、预算和版本；清理输出后独立重跑。 |
| 版本可比性 | 更改题目或答案后建立新版本，保存可比子集和变更说明。 |

**补充顺序**：先把数据质量与评分可靠性做成所有题包的共同门槛，再决定是否扩展公共卫生独立任务。新增类别需要实际任务和来源，不能只补一个分类名称。


## 六、需求、买方与经济价值

| 潜在买方 | 需要决定什么 | 可交付的评测产品 | 要验证的收益 |
| --- | --- | --- | --- |
| 模型 / Agent 团队 | 新版本是否可以发布或替代旧版本 | 任务集、失败归因、版本回归与预算对照 | 严重错误减少；同预算成功率提升 |
| 药企 / 生物技术团队 | 候选和分析方案是否进入下一步 | 私有测量集、候选排序、适用域与校准 | 固定实验预算下的命中或筛选增益 |
| 科研软件 / 计算平台 | 工具与自动化流程是否可靠 | 可重跑工作流、工具失败集与兼容性回归 | 返工减少；完成率和复核时间改善 |
| 医院 / 医疗产品团队 | 本地场景和新模型是否安全适用 | 本地病例回归、风险分层与专家复核 | 关键漏报、流程负担和升级人工行为 |
| 研究机构 / 挑战社区 | 方法比较是否公平和可持续 | 公开协议、版本化数据和盲测 | 复现性、参与度和方法比较可信度 |

这是需求假设与产品映射，不能当作已签约客户名单。公开排行榜和论文采用可以证明研究使用，付费意愿需要采购、试点或客户访谈等不同证据。


### 可以计算的价值

净价值 = 节省的专家与计算成本 + 减少返工的成本 + 可核验的决策收益 - 推理、数据维护、专家复核和部署成本。不同项需要独立测量，避免把时间节省与项目收益重复相加。

试点最先记录：每个合格任务的全成本、专家复核分钟数、严重错误率、干净重跑成功率、固定实验预算下的候选命中率。不要从药物研发或医疗行业总规模直接推导 Benchmark 的市场规模。

**明确的采用线索**：MedBench 的官方平台更新提供累计评测使用信息，可支持“存在重复评测需求”的线索。其统计范围与本目录 45 条样本不同，也未直接披露本报告可核算的评测收入。[R09]

| 阶段 | 具体交付 | 推进条件 |
| --- | --- | --- |
| 公开研究入口 | 报告、来源版图、窄域任务样例和可复现结果 | 能说明评测检验的科学错误；版本与许可可追溯 |

## 八、可先启动的两种最小试点


### 试点 A：单细胞 / 扰动分析的科学验收

| 项目 | 建议任务 |
| --- | --- |
| 输入 | 获准使用的表达数据、细胞与生物重复信息、扰动与对照标签；冻结数据划分和目标估计量。 |
| 模型工作 | 质控、批次与重复诊断、基线比较、效应估计，输出可运行代码和结果解释。 |
| 客观评分 | 效应方向与估计误差、置信区间、预注册负控、未见条件表现；组合任务检验非相加效应。 |
| 有效负控 | 标签置换、无变化或均值基线、只利用批次信息的捷径；确认参考结论在数据中可识别。 |
| 完成标准 | 独立重跑、等价方法可通过、错误方法可被拦下；准确性与执行成本分开报告。 |

双扰动题可使用 Δint = (AB - C) - (A - C) - (B - C)。若在变换后的表达尺度上计算，必须在公开任务中写清尺度、对照与重复单位。模型不应仅凭总体表达相关性获得成功。


### 试点 B：可追溯证据检索与更新

| 项目 | 建议任务 |
| --- | --- |
| 输入 | 一组有限且获准使用的论文或来源快照，明确问题、截止时间与可访问资料。 |
| 模型工作 | 检索支持与反对证据，回答限定主张，定位来源并处理无法确认的信息。 |
| 评分 | 主张是否被证据直接支持、引用可定位、反证覆盖、时间约束与弃答质量。 |
| 完成标准 | 专家盲审样例与自动引用检查相符；每条有效证据与复核成本可测量。 |

**任务规模怎么定**：先挑能独立核验的小样例，按失败模式覆盖增加数量；达到稳定评分后再做功效或样本量设计。任何演示集的成功率都不能直接外推到完整领域。


## 九、实施路线与验收标准

| 阶段 | 具体工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 第 1-2 周：来源与协议 | 核验优先来源、机构角色、版本和许可；明确目标客户决策与主评测单位。 | 每条重要主张有来源；所需数据能合法使用；选择一个窄域试点。 |
| 第 3-4 周：参考与评分 | 完成参考解、负控、等价解、评分阈值与执行环境；建立干净重跑。 | 正确方法通过；错误与捷径样例失败；评分分歧可以解释。 |
| 第 5-8 周：模型对照 | 在同一协议与预算下比较若干模型配置，记录成功、成本和失败归因。 | 指标与版本绑定；结果可重跑；能说明任务对模型的区分来自哪里。 |
| 第 9-12 周：场景试点 | 在获授权的用户场景中验证复核时间、错误率和真实决策增益。 | 用户认为结果能改变其选择；收益覆盖交付成本；是否继续使用有证据。 |


### 正式发布前的共同检查

科学性：目标可识别，基线合理，重复单位正确，统计假设与评分范围一致。公平性：公开任务说明已披露全部评分义务，允许科学等价解。可复现性：数据、工具、版本和预算固定，评分证据来自实际执行。

报告指标应包括分层成功率及不确定性、严重错误率、重跑一致性、人工复核成本与每个有效任务成本。难度和轨迹长度分别报告；长时间运行不是任务价值或科学成功的替代指标。


### 下一次版图更新应新增什么

建议新增逐主张的来源记录：机构角色、Benchmark 版本、核验状态、采用信号、适用范围、来源时间与访问时间。对 BixBench 合作署名、MedBench 平台采用等差异单独登记，保持历史与新证据的可比较性。

**本报告结论**：本项目可以发展为生物医药 AI 能力与评测情报入口。第一步应证明一个窄域任务能可靠区分有效和无效方法，第二步验证它是否改变真实用户的选择，再据此扩大数据和服务范围。
