# 搜索受限修复记录（2026-10-08）

## 已确认的原因

用户失败任务为“全志科技”。原实现只请求 360 搜索，且只检查 HTTP 状态码。
复现请求返回 HTTP 200，但页面标题为“访问异常页面”，正文要求输入验证码。
旧解析器找不到结果节点，把访问限制和无匹配结果混在同一错误中。该失败发生在写入 Obsidian 之前。
页面将异常网络/IP 请求列为可能原因；无法仅据此证明是本项目导致，或确定共享网络、代理等因素的影响。

## 修复

1. 默认搜狗 → 360 的独立搜索源选择；可选环境变量启用正式 Brave Search API。
2. 识别 HTTP 200 验证页、403/429、无匹配结果和页面解析失败；显示每个搜索源的诊断。
3. 同名同参数搜索缓存 6 小时，保留原搜索时间；搜索源间隔 5 秒，受限暂停至少 30 分钟，状态跨重启保存。
4. 仍检查公司名称匹配，不为了“成功”而保存无关信息；不解决或绕过验证码。
5. UI 展示实际搜索来源和缓存状态。程序负责从搜索到入库，不手工补填公司数据。

## 验证

- 全志科技：搜狗，6 条线索，2 个网页摘录，实际写入用户仓库。
- 宇树科技：搜狗，6 条线索，2 个网页摘录，实际写入用户仓库。
- 宁德时代：从实际 UI 搜索，6 条线索，2 个网页摘录，界面显示已写入笔记库。
- 23 项回归测试通过，覆盖验证页识别、备用源、持久暂停、缓存免请求、请求间隔、错误分类、已有笔记保护和 UI 接口。

备用源无法消除所有第三方限制。若全部服务均不可用，程序明确报错，不冒充完成。
