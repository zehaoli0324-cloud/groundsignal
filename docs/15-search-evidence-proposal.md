# Proposal：GroundSignal 可审计搜索与证据采集管线

日期：2026-10-19（Asia/Shanghai）。范围：半导体企业与供应链情报；仓库为 groundsignal。

## 1. 要解决的问题

现有 `collect.py` 能搜索公司、保存网页线索，但不能系统回答：某家公司的供应商、客户、竞争者、投资方、被投资方及关键人物分别是谁，关系适用于哪个产品、什么时间和商业阶段，有哪些原文支持或反对。

当前主分支的来源域名评级不能作为关系真伪验证。搜索摘要、公司官网链接和节点级来源不能直接升级为已确认关系。草稿 PR #3 已提供证据账本、独立来源归并、明确审核和时间回放，本方案复用该接口，不另建一套事实状态系统。

目标是建立可以重放、检查、比较成本的生产流程：

研究目标 → 分维度搜索计划 → 多源检索/固定来源 → 原文快照 → 候选关系抽取 → 程序校验 → 大模型按需复核 → 人工审核 → 既有账本与公司卡。

## 2. 采集范围与边界

| 维度 | 保存的内容 | 必须区分 |
|---|---|---|
| 上游 | 材料、设备、代工、封装、软件、分销等供应关系 | 集团/子公司、产品、送样/认证/订单/出货 |
| 下游 | 直接客户、渠道、最终用户、采购方 | 客户与生态伙伴；招标与中标；订单与交付 |
| 同类 | 直接竞争、替代产品、产品重叠、共同客户/生态 | 共享客户不是竞争已成立 |
| 投资方 | 投资事件、当前及历史持股 | 基金、管理机构、实际出资主体 |
| 被投资方 | 少数投资、控股、全资、合营 | 投资不是控股，最大股东不是实控人 |
| 关键人物 | 创始人、联合创始人、管理层、实控人 | 人物角色、任期与同名身份 |
| 产品与技术 | 产品代际、应用、替代方案、商业化阶段 | 宣传、规划与已实现能力 |
| 设施与产能 | 工厂、产线、扩产、投产与利用率 | 公司级与设施级；估计与披露 |
| 反证与变化 | 否认、终止、更正、替代、延期、过期 | 未找到证据不代表关系不存在 |

证据可靠性、合作紧密程度、商业重要性分别记录。采集范围可以稍宽，核心公司卡只展示通过审核且相关性足够的记录；重要但未核实的内容进入调查队列。

## 3. 选型决策：根据项目验收，不宣称存在通用“最强”

| 层次 | 第一选择 | 对照/后续 | 选择理由 |
|---|---|---|---|
| 搜索 | Brave / Tavily 的独立适配器 | Firecrawl Search、DeepSeek Search | 保留原始命中、错误、查询和消耗；独立比较中文召回 |
| 已知来源 | 官方来源注册表与种子 URL | RSS/公告 API/站内列表适配器 | 关键来源不完全依赖搜索引擎排名 |
| 正文 | 轻量 HTTP；动态页可选 Crawl4AI | Crawlee、Firecrawl | 先复用现有 Python 栈；按页面需要选择浏览器 |
| PDF | 可选 pypdf / Docling | OCR 按失败类别增加 | 保留页码与表格解析边界 |
| 抽取 | 有 Schema 与精确引文约束的模型适配器 | LangExtract 的定位和可视化 | 先把来源绑定与审核接口跑通 |
| 小模型 | Qwen3.5-9B；4B 作低成本对照 | 后续根据实测更换 | 常规抽取、字段归一；不按自报 confidence 自动确认 |
| 大模型 | 可配置的 DeepSeek Flash / Pro | 其他兼容服务作为独立基线 | 复杂主体、所有权、否定/传闻、格式失败与抽样复核 |
| 流程 | 有限步骤的 Python 管线 | LangGraph | 当前阶段便于调试、复现与成本约束 |
| 整理与审核 | PR #3 证据账本；借鉴 DisMech/mechmaker | 公司卡与变化清单 | 程序验证与领域判断分开 |

2026-10-19 核查：DeepSeek 官方文档当前列出 `deepseek-flash` 和 `deepseek-v4-pro`。服务别名可能变化，必须记录请求模型、返回模型、端点、提示词哈希、配置哈希、用量与运行时间；不把别名当作不可变模型版本。具体中文行业质量尚未实测。

## 4. Skill 与 Agent 的用法

- Firecrawl 官方 CLI/skills：作为搜索、抓取、浏览操作流程的参考；其开源代码不等于云服务免费。
- Browser Use：只在固定采集与常规浏览器渲染不足时处理多步交互，输出仍是候选证据。
- DisMech/mechmaker：借鉴结构化记录、原文核验、主张–证据匹配审核、变更历史与人工合入；不照搬医学本体。
- LangExtract：后续比较字符定位、长文分块、多次抽取和可视化对人工审核效率的贡献。
- Open Deep Research / GPT Researcher：作为开放检索与研究报告对照，不直接写正式关系。
- SKILLER：研究“大模型分析失败并改善小模型工作说明”的思路。当前公开代码为 PolyForm Noncommercial，暂不引入代码、不启动在线自优化；只有在训练/开发/测试隔离后再评估。

第一版使用仓库内版本化 prompt 与确定性工具，不全局安装或覆盖用户已有 Agent 的搜索设置。网页、搜索摘要和 PDF 均为待分析的数据，不能改变系统指令、调用工具或批准入库。

## 5. 小模型与大模型的路由

1. 规则生成覆盖九维度的搜索任务，限定查询、命中、页面、模型调用和超时预算。
2. 搜索服务返回 URL 与摘要；程序规范化 URL、聚合命中、按主体别名与来源类型排序。搜索提供商数量不等于独立来源数量。
3. 抓取原文，保存文本、内容指纹、首次观察/抓取时间、解析方式、页码/段落与失败原因。搜索摘要不能冒充原文。
4. 小模型从保存的文本抽取原子候选：主体、谓词、客体、产品、阶段、肯定/否定/不确定、事件时间、逐字引文。
5. 程序校验输出结构、枚举、引文位置、主体/客体定位及阶段越级。无效候选被隔离，不被静默丢弃或当作成功。
6. 复杂所有权/实控、竞争推断、否定/传闻、格式或引文失败等升级大模型；另对正常样本做确定性抽样复核，以发现小模型未自报的错误。
7. 大模型只能给候选和复核意见；分歧保留在审核队列。两个模型意见一致不构成两份独立证据。
8. 所有候选进入待审核队列，交给 PR #3 的明确审核入口；程序不能根据来源域名或模型自评分生成 `VERIFIED`。

允许 `small_only / large_only / cascade` 三种模式，在同一批冻结原文上比较，避免把搜索差异误判为模型能力差异。未配置模型必须显示 `MODEL_NOT_RUN`；无可用搜索源必须显示缺配置或受限，不能生成模拟成功。

## 6. 数据契约

以 `research-target`、`search-plan`、`search-run` 和原子 `candidate` 记录搜索工作；以 PR #3 ledger 保存交接结果。

| 对象 | 关键字段 |
|---|---|
| Target | 稳定研究 ID、名称/别名、身份确认状态、官方域名、时间范围、维度 |
| Query | 查询 ID、维度、原样查询、来源约束、检索目的 |
| Hit | provider、query_id、排名、URL、标题、摘要、搜索时间 |
| Document | URL/最终 URL、文本/页码、指纹、正文获取状态、抓取时间、来源类型提示 |
| Candidate | document_id、主体/关系/客体、产品/阶段、极性、原文引文与区间、审核标记 |
| ModelAttempt | 角色、请求/返回模型、提示词/配置哈希、用量、耗时、结果或错误码 |
| Run | 模式、预算、实际请求数、诊断、覆盖缺口、真实/合成标记、交接文件 |

未知时间不补造具体日期，未知身份不认作工商主体已确认。同域不必然同源，跨域不必然独立；第一版只记录可确认的重复，不自动认定独立。来源品质与事实支撑强度分开。来源快照、模型重跑与审核保留独立时间，不改写历史 first_seen。

## 7. 实施阶段与验收

### P0：本轮搭建

- [x] 九维度搜索计划、预算和目标配置。
- [x] 多源检索适配器、URL 去重、来源注册表与错误诊断。
- [x] 原文获取、正文与指纹保存；动态页/PDF 可选适配器。
- [x] 小/大模型统一接口、三种路由、精确引文检查和升级原因。
- [x] 待审核候选与 PR #3 ledger 交接，不自动确认关系。
- [x] 可运行 CLI、合成离线演示、测试与真实网页 smoke 记录。
- [x] 对照评测入口；没有运行的服务/模型明确 NOT_RUN。

### P1：真实试点

- [ ] 5 家半导体公司 × 官方/公告/行业媒体三类来源。
- [ ] 人工标注 100–200 条样本，包含同名、历史、传闻、否定、转载与商业阶段负例。
- [ ] 按公司/来源组/时间划分开发与留出集，防止改 prompt 看到测试答案。
- [ ] 在同一冻结材料上比较无模型、9B、4B、大模型与级联。
- [ ] 连续两周运行，计算已定义来源/时间范围内的覆盖、漏报、错误、延迟与成本。

### P2：有证据后扩展

- [ ] 公告 API、RSS、站内列表和持续去重队列。
- [ ] 证据高亮审核界面、实体归一与来源独立性人工确认。
- [ ] 按错误类型增加 LangExtract/Docling/Browser Use 与必要的编排。
- [ ] 基于开发集改善工作说明；只有可重复的内容错误才考虑微调。

首轮技术验收：无来源候选不能入账；摘要不能冒充正文；模型不能写审核结论；同内容不能伪装多源；缺密钥不能报完成；超预算停止并报告；所有新增正式事实仍需显式审核。

真实试点建议目标（不是当前成绩或商业承诺）：关系精度 ≥95%，原文定位准确率 ≥99%；报告字段级精度/召回、拒答、已知事件覆盖、误报、成本及样本量/区间。已收集样本的精度不能代替全行业召回率。

## 8. 初始交付及依赖

工程交付为新分支与 PR，不直接合并 main。新分支包含 main 与 PR #3 的代码以便验证；原 PR #3 继续保持未合并，后续按依赖顺序审阅。

当前运行环境无 Brave/Tavily/Firecrawl/DeepSeek/通用模型 API 密钥，且未运行本地 Qwen 服务。因此本轮先证明工程闭环、失败边界和可访问的真实网页；模型优劣、付费 API 连通性与行业数据质量继续标为未实测。不会把合成 fixture 的测试成功写成真实研究结果。
