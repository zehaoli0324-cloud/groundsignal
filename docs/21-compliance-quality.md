# 合规与数据质量方案

本方案面向半导体公司公开信息研究，核对日期 2026-10-19。法律部分以中国现行相关官方文本为起点，具体来源、部署地、用户、供应商及数据流可能引入其他地区要求；项目实施时按实际场景核对。本文件是操作方案，不是对任意网站或商业数据产品的合规认证。

## 第一步：把五项权利分别核对

**用途：** 避免用“网上能打开”代替完整授权判断。

每个来源登记：是否允许自动访问、能否本地保存全文、能否抽取建库、能否交给特定第三方模型、能否对外分享。条款、许可证、合同及查验日期放入 [研究审核模板](templates/research-review.md)，逐项写允许、禁止或待核实及依据；付费 API 也不当然包含上游内容再分发权。

**产物与验收：** 每份实际采集内容能对应一个准入记录；未知项不默认允许。商业数据产品、转载全文、数据库批量导出需要另行核对权利。

**失败处理：** 来源权限不清时先使用允许的链接和必要元数据，不调用下载全文；需要登录 / 订阅的数据只走明确授权渠道。著作权法的有限例外不能被扩大为任意商业转载全文的许可。依据：[著作权法官方全文](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)第 24、26、29 条。

## 第二步：控制访问方式和负载

**用途：** 保护来源服务，留下可解释的技术行为，不把访问受阻当作需要绕开的障碍。

- 默认 HTTP 抓取检查 robots、URL、DNS、重定向、内容类型、长度及访问失败；单次超时、次数和总时长分别有预算。顺序执行，遇 429 按 Retry-After 暂停；禁止开多个进程规避限流。
- robots 是自动访问规则，不是著作权或法律授权。robots 缺失也不是内容可任意使用的凭证；代码对不同状态的保守处理只是工程策略。
- 验证码、账号墙、付费墙、明确拒绝、异常负载时停止来源；不使用换 IP / 账号池、会话窃取或破坏访问控制来继续抓取。抓取器的识别有局限，仍需抽查原页面。
- 可选浏览器会请求子资源，当前预算只计 renderer 调用；部署方必须额外隔离网络、阻止私网访问及不必要资源。默认 HTTP 路径不能替可选浏览器提供相同保证。

**产物与验收：** 请求量、错误、暂停与停止原因可查；没有越权访问或给来源造成明显负载。

**失败处理：** 服务拒绝访问时联系来源方或换获准来源，不通过提高重试量解决。依据：[RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html)说明 robots 不构成访问授权；[2025 修订反不正当竞争法官方全文](https://zscqj.beijing.gov.cn/zscqj/zwgk/flfg18/436481051/index.html)第 10、13 条涉及商业秘密、不正当获取使用数据及妨碍网络服务等边界。

## 第三步：把关键人物信息限于研究所需

**用途：** 区分公司关系研究与无关个人画像。

仅保留有研究必要的公开职务、任职时间、创始 / 控制关系及其依据。不采集私人电话、住址、身份证号、家庭成员、健康、行踪等无关信息；依法公开的信息也要核对处理目的和合理范围。公开名片、联系方式不因为可搜索就适合批量入库。

**产物与验收：** 人物字段能解释其必要性及来源；设置最短必要保留期限、访问角色、更正 / 删除联系人和处理记录。采集意外包含无关个人信息时隔离处理，不继续发送模型或分享。

**失败处理：** 现管线不做可靠自动脱敏，原始 bytes、解析文本、run、账本和导出可能含同一信息。不能只删 UI 上的一行就认为全删；需覆盖缓存、备份、派生文件与第三方副本，依法处理应留存情形。来源原件需要改动时不能直接修改冻结 run 绕过指纹；重新建立获准输入及变更记录，或排除该材料。

依据：[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)关于必要性、保存期限、公开个人信息处理范围与安全义务；[网络数据安全管理条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)第 24 条涉及自动采集造成的非必要或未依法取得同意的个人信息处置。

## 第四步：在发送外部模型前核对数据流

**用途：** 防止“只做分析”的配置意外向外传输正文或个人信息。

| 流向 | 会发送 / 保存什么 | 人工核对内容 |
|---|---|---|
| 搜索 API | 公司 / 个人名称、查询词、账号与请求元数据 | 查询本身是否含内部计划、未披露交易；API 条款、存储地点 |
| 目标网站 | URL、来源服务器可见的网络请求信息 | 自动访问权限、负载与识别方式 |
| 本地存储 | 原始网页 / PDF、正文、候选、提示 / 输入指纹、审核与导出 | 权限、加密、备份、保留、删除、对外分享范围 |
| 本地模型 | 选定正文片段和目标配置 | 确实为 loopback 服务；运行环境有无额外外传机制 |
| 云端模型 | 选定正文片段、目标及抽取 prompt | 委托 / 提供关系、合同、训练用途、日志保留、分包、目的地、个人信息及出境适用条件 |

**产物与验收：** 第三方模型处理权和数据流记录可查，所用服务及地域明确。不能因供应商品牌判断服务器、日志或分包的真实位置；是否适用跨境要求要结合数据类别、主体和实际路径核对，不能笼统断言所有调用都必须或都无需某一种程序。

**失败处理：** 权限不明时先 `--models none` 采集获准来源，或本地 `small_only` 且禁用 large；cascade 会触发云端升级，不能称纯本地。本版没有“外发前逐源许可检查 / 自动脱敏”技术门禁，要靠操作者分离批次和配置，未完成准入的批次不运行云抽取。涉及商业秘密、未公开交易、受合同限制数据不进入该公开研究流程。

依据：[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)第 21、38–40 条及[网络数据安全管理条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)相关数据处理与跨境规则；使用时核对最新适用规定和供应商合同，不把模型可访问视为授权证明。

## 第五步：给质量拆层，不给一个虚假“可信分”

**用途：** 让每种问题找到对应检查，避免高结构分掩盖语义错误。

| 质量层 | 要核对的问题 | 已有程序支持 | 仍需人工或后续实现 |
|---|---|---|---|
| 获取与来源 | 拿到原件还是搜索摘要 / 转载？ | 分离命中与正文、获取状态、来源提示、bytes 与文本指纹 | 发布者真实性、内容权利、原件是否最终版 |
| 主体 | 两个名字是否同一法人？ | 别名匹配、候选保持 UNCONFIRMED | 注册 / 证券标识、母子公司、历史更名、匿名对象 |
| 结构与引文 | JSON 完整吗？引文确在输入和原文吗？ | Schema、精确区间、PDF 页码（pypdf）、字段部分检查 | 表格、跨段语义、Docling 输出页码可靠性 |
| 含义与阶段 | 方向、否定、数量、测试 / 量产是否正确？ | 部分阶段 / 日期 / 极性线索检查、模型分歧保留 | 全面语义审核、金额 / 份额 / 单位、条件与限定 |
| 独立性 | 多份材料是否同一通稿？ | URL 规范化、完全相同文本提示 | 原始发布链、改写转载、真正独立信息源 |
| 时间 | 发布时间、事件时间、抓取时间是否混淆？ | 抓取 / 首见时间、有限事件日期字段、冻结重跑 | 生效 / 失效、回溯披露、当前有效性、类型化复查周期 |
| 覆盖与偏差 | 没找到是没发生，还是没搜到？ | 查询和维度计数、失败 / 预算缺口 | 长尾、小公司、非英文 / 中文材料、非公开市场的系统偏差 |
| 发布与治理 | 是否可用、可分享、可删除？ | 待审候选、ledger 未确认交接 | 逐候选裁决入图、许可门禁、全副本删除、审计权限 |

`validate` 只说明合同与保存输入的完整性；`audit` 只说明技术运行；两个模型一致也不证明事实正确。模型自报置信度不作为正式可信度，来源 T1 提示也不自动变成主张 VERIFIED。

## 第六步：建立金标与批次验收

**用途：** 用可复验样本决定是否采用某模型及能否输出结果。

1. **分层取样。** 先选 5 家公司、100–200 条主张；覆盖中英文、官网 / 监管 / 媒体、所有九维、长 PDF、表格、转载、否定与时间变化。另加入确实无相关主张的正文。用途：避免只测容易样本；这是初始实验规模，不代表全行业覆盖。
2. **两人标注与裁决。** 独立读原文，记录主体、关系、产品、阶段、极性、事件时间和证据；分歧单独裁决。用途：金标也可能错，不能由待评模型生成后原样当真。
3. **分开开发与留出。** 按公司 / 原始文档及其转载组划分；留出答案不进入 prompt。用途：避免同源泄漏和反复调到高分。
4. **冻结输入再比较。** compare 三组使用相同文本和 SHA；记录代码、prompt、配置、请求 / 返回模型与供应商版本。用途：把模型差异与抓取变化分开。
5. **检查分项指标再看总分。** 报告分母、严重错误、人工时间及实际费用。用途：不让某个常见关系掩盖实控、否定等稀有高风险错误。
6. **未达门槛继续待审。** 先修证据、解析、实体或 prompt，再用新留出样本复验。用途：不通过降低规则或隐去失败让系统“上线”。

以下是**建议的首轮试点门槛**，尚无真实实验达到这些值：

| 指标 | 定义 / 分母 | 建议门槛及含义 |
|---|---|---|
| 可追溯性 | 拟纳入结论的主张中，有原文 ID / SHA / 引文位置 / 审核人的比例 | 100%；缺任何项不纳入正式结论 |
| 人工主张精确率 | 人工确认正确的候选 / 被审核的候选；同时拆关系、语言、来源 | 初始目标 ≥95%；必须披露样本数和不确定性，不能转为自动放行率 |
| 严重错误 | 方向颠倒、编造对象、否定变肯定、少数股权变实控、送样变量产等 | 拟发布集合为 0；发现即复查同类样本与批次 |
| 高风险复审率 | 有第二位人类复审的高风险主张 / 拟发布高风险主张 | 100%；不足就注明未完成并暂缓相关结论 |
| 抽取召回率 | 正确抽出的金标主张 / 已标注原文中的全部金标主张 | 记录并逐维改进；不是全网或全行业召回率 |
| 覆盖披露率 | 已说明证据 / 缺口 / 未执行原因的维度 / 本轮研究维度 | 100%；不要求每维硬凑关系 |
| 许可与保留记录 | 本次使用来源中准入及处置范围明确的比例 | 本轮使用的来源 100%；待核实来源不视为通过 |

compare 内置评分是严格字段元组匹配，限于有金标的文档子集；上述实体、独立性、权利、人工精确率与最终发布门槛不由 compare 自动计算。初期逐条审核所有拟输出主张；积累稳定数据后才考虑低风险抽样，且高风险继续全审。小样本“零错误”仍不足以证明零风险，例如 100 条未见错误，错误率的常用近似 95% 上界仍约 3%。

## 第七步：把质量问题分流修复

**用途：** 区分基础设施、信息不足、模型错误和治理问题，避免所有问题都靠加大模型。

| 发现 | 应采取的动作 | 不能采取的捷径 |
|---|---|---|
| DNS / 鉴权 / 429 / robots 拒绝 | 修网络或配置；暂停并换允许来源 | 伪造空结果、绕过控制、反复重试 |
| 正文不完整、扫描 PDF、表格丢失 | 人工看原件；另做获准 OCR / 解析试验，保留版本 | 让模型补写“缺页” |
| 同名、匿名、方向错 | 人工归一、缩小主张、加入失败样本 | 用模型置信分压过身份缺口 |
| 提示注入 / 网页指令 | 将来源当不可信材料；固定无工具抽取 prompt，严格输出检查 | 让网页要求决定访问、执行命令或上传材料 |
| 原文互相冲突、旧结论被更正 | 保留双方与时序，暂停相关正式结论 | 静默删除反证或覆盖旧证据 |
| 敏感信息 / 权利投诉 | 隔离批次、暂停处理 / 分享，核对并依法处置相关副本 | 只删公开页面，继续在云模型和备份中使用 |

当前模型抽取接口没有工具执行权限，降低了网页指令直接驱动动作的风险；不能据此保证语义上免疫提示注入。原始内容和模型输出均视为不可信输入。

## 实施顺序与明确缺口

先落实来源记录、单批预算、人工全审、受控文件保管和真实留出评测。下一阶段再实现逐源抓取 / 外发许可门禁、人物字段最小化与脱敏 lineage、主体归一、逐候选裁决入图、来源链归并、关系有效期、跨任务预算和访问审计。

本轮新增的 prepare / doctor / audit 不承担法律授权判断、自动审核结论、递归图搜索或商业发布能力。只有把上述缺口真正实现并验证后，才能逐步减少人工步骤。
